GIT can be thought of as below :
1) Workspace ---> 2) staged area ---> 3) Commit to local repo ---> 4) remote repository 

  To have changes in 1 to transfer to 2 
  git add .

  To have changes in 2 to transfer to 3 
  git commit -m 'commit message'  

  To have changes from 3 to 4
  git push

  To have changes from 4 to 1 
  git pull

# GIT MERGE VS GIT REBASE 
   Merge is used to blend changes from one branch to another .
   In this merge source branch can continue even after merging unless explicitly deleting the branch

   Rebase is used similar to git merge but the source branch will be removed after merge,
   by making target branch as the base for even source branch

# Solve Pull issue : (Could be wrong study in detail later)
      There are two ways , You can either 
         1) Run commands that will specificaly affect this particular pull issue , not the future ones .
         2) Or Run the commands which will modify the CONFIG of this repo , so that this config change 
            gives the info to GIT on how to handle even future PULL issues.


      WAY 1 : (elaborate later right now I dont have time)
         Use any of the below based on your requirement
            > git pull origin <branch-name> --no-rebase
            > git pull origin <branch-name> --rebase

      WAY 2 : (elaborate later right now I dont have time)
         Use any of the below three commands based on your requirement
            > git config pull.rebase false # merge
            > git config pull.rebase true # rebase
            > git config pull.ff only # fast-forward only
